# Kriko 0.3.3 verification — Windows x64

Built locally on 2026-10-24 from PR #278's branch,
`fix/agent-search-and-shared-access`, which carries the settings reorganisation
from PR #277. Source commit `2d9604df`; the release tag adds only this record.
The maintainer asked for publication after friends' feedback, knowing the
limits below.

## What changed for readers

- A local model can search the web through DeepSeek (a key, an access code or
  the trial) without OpenSERP running. Before, it was refused with "no local
  search service".
- DeepSeek leads the web-search order whenever it can be asked; OpenSERP is used
  only when the reader chooses it or nothing else can answer.
- Kriko Agent keeps researching when the reader answers its question or
  corrects it, instead of answering from memory.
- Follow-up suggestions are phrased as things the reader could ask next, and
  suggestions addressed to the reader are dropped.
- The run timeline starts folded; sources live in the right-hand rail; more
  than two products fold into a list; Alternatives, Cheapest and Merchants say
  what they do.
- The long-chat warning follows a character budget instead of a fixed eight
  messages.
- The browser extension shows Kriko Agent as unavailable, with the reason,
  when it is not set up (extension 0.4.5).

## Checks completed

- Full Python gate, run on its own because the full parallel run exhausted
  memory on this machine: 4,561 passed, 23 skipped; lint, type checks and
  version agreement passed.
- Extension: 514 tests. UI: build, TypeScript, lint and behaviour tests.
  Website: 13. Native shell: cargo check and 13 Rust tests. These ran in the
  same parallel run in which the Python stage failed on memory.
- The frozen engine passed the standard health, settings, empty-store, lookup,
  failing-job, MCP and terminal smoke checks.
- The native desktop app stayed up for 25 seconds, did not panic, and spawned
  its bundled engine.
- The installer, extracted with 7-Zip, holds the app, the engine and OpenSERP
  and no catalogs; its engine started in 2.4 seconds on a throwaway profile
  and answered the health check.
- Demo-mode check in Chrome against the dev server: the chip explanation line,
  the folded timeline and the wider thread column.

## Not observed

- A clean install, running the installer, an upgrade from 0.3.2, and the
  extracted portable copy. The installer was not run on this machine; it was
  extracted with 7-Zip instead (see above).
- Any live research on the packaged build: local-model search through DeepSeek,
  and Kriko Agent carrying on after an answer, are covered by automated tests
  only.
- The folding product list and follow-up suggestions on screen (demo mode
  produced neither); the packaged window at 125% scaling; the extension in a
  real browser.
- PR #276's limitation remains: downloading a harvested `.kpack` from the
  packaged window is unavailable.

## Packaging notes

- The engine is now frozen from the locked environment alone. Compared with
  0.3.2 it no longer carries pandas, scipy, lxml, aiohttp, the Google client
  libraries and similar packages that the source never imports; the engine zip
  is 29 MB against 92 MB and the installer 33 MB against 80 MB. The smoke
  checks above passed on it.
- OpenSERP 0.8.12 is still bundled and verified against its pinned digest.
- The updater manifest requires shell 0.3.2.
- No catalogs ship with this release.
- SHA256SUMS.txt covers the installer, portable ZIP, engine ZIP and extension
  ZIP.
