# Kriko 0.3.2 verification — Windows x64

Built locally on 2026-10-23 from PR #276's branch,
`fix/agent-search-and-shared-access`. Desktop source changes are committed in
`aa4a96f1`; the release tag also includes this verification record. The maintainer
requested publication after the validation limits below were disclosed.

## Checks completed

- Full Python gate: 4,546 passed, 23 skipped; lint, type checks and version
  agreement passed. Targeted tests also passed after the final source-follow-up
  routing, page-reader transport and text-only prompt changes.
- Extension: 512 tests passed, including manual opening and quiet background
  results on known sites, unknown sites, cached results and unknown products.
- UI: production build, TypeScript and lint passed; all 91 behavior tests passed.
  The initial lint failure from a callback name was fixed and this gate rerun.
- Website: 13 tests passed. Native shell: cargo check and 13 Rust tests passed.
- The wheel installed into an empty environment and its command reported 0.3.2.
- The frozen engine passed the standard health, settings, empty-store, MCP,
  benchmark and terminal smoke checks.
- The native desktop app stayed up for 25 seconds, did not panic, and spawned
  its bundled engine.

## Live test against the frozen engine

A separate Windows profile had no personal provider keys and no trial bundle.
It opened a shared-access code using this build and Windows DPAPI protection.

| Action | Result |
|---|---|
| Unlock shared access and discover Kriko Agent | Passed |
| Check connection | Passed, 2.1 seconds |
| Read the official Raspberry Pi 5 product page and answer a specification question | Passed, 12.2 seconds, source trail retained |
| Ask which power supply that page recommends | Passed, 11.3 seconds, answered in the same conversation with sources |
| Forget the shared keys | Passed; grant absent afterwards |

Additional live questions exercised unavailable manual pages and provider
fallback. A successful job is not a promise that every requested page can be
read. The app must identify an evidence gap when a source cannot be verified.
No test access code, password or provider key is included in these artifacts.

## Packaging and remaining manual checks

The standard Windows recipe completed the engine freeze and smoke checks. It
then encountered a dependency locked by a running development Vite server.
After stopping that server, the remaining npm, Tauri, native smoke and portable
packaging steps were resumed. The development server was restored afterwards.
An abandoned, empty Pydantic metadata directory was moved aside to repair the
build environment; the active runtime remains pydantic-core 2.50.1.

- Installer installation/uninstallation was not tested: this machine already
  has Kriko installed, and the smoke deliberately refuses to replace it.
- Screenshots and a live browser extension check were unavailable because the
  desktop automation helper and browser surfaces were unavailable. A visual
  pass at 125% scaling remains outstanding.
- PR #276's existing limitation remains: downloading a harvested `.kpack` from
  the packaged window is unavailable; that binary download needs a native
  streaming command.
- Extension 0.4.4 is included separately. An older store extension retains its
  old behavior until updated; see TESTING-0.3.2.md for testing this ZIP.

SHA256SUMS.txt covers the installer, portable ZIP, engine ZIP and extension ZIP.

The release updater manifest requires shell 0.3.2 so an older installation
receives the full installer and its new setup UI. This packaging metadata was
updated and the engine ZIP regenerated before publication. No catalogs ship
with this release, as with 0.3.1.

Publication checks corrected the updater tests to require shell 0.3.2.
A model-discovery concurrency test now uses a two-worker barrier rather than a
wall-clock comparison; 26 targeted updater and concurrency checks passed.
