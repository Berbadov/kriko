# Kriko 0.3.12 verification

Cut from `main` after merging #339 (CLI rebuild + Estimate screen), #340 (the
gate runs light by default, with the serial-gate red fix) and #341 (a resident
agent session that times out empty marks the harness unhealthy, closing #337).
The extension keeps its 0.5.0 manifest; the website and the phone app live in
their own repositories (#335) and are untouched by this release.

## What changed for readers

- **The desktop CLI is fast and consistent.** `--version` answers in ~0.24 s
  (it no longer imports the provider stack), and the read commands (`prefs`,
  `costs`, `sites list`, `verify --list`, `drafts list/show`, `operations`)
  read `app.sqlite` directly, so they answer in ~250 ms whether or not an
  engine is running. Every command takes `--json`; human output is unchanged.
- **A new Estimate screen.** Equipment lines from the installed catalogs with
  quantity and unit price, known issues per line with a Research button, the
  subtotal plus research spend and the next run's estimated cost, a
  depreciation/NPV forecast over 1–30 years, named saved estimates, and Excel
  (.xlsx) or CSV export.
- **A stalled agent session no longer eats a chat turn (#337).** A persistent
  session that times out with nothing delivered is marked unhealthy for ten
  minutes; the turn's later calls run in a fresh process instead of paying the
  same 30 s timeout again until the 90 s budget is gone.

## What was and was not observed

See `0.3.12.json`. The full gate ran on `main` in this Linux sandbox: the `py`
stage (version agreement, ruff, four mypy runs, pytest 5171 passed / 0 failed),
`wheel`, `node` and `ui` stages all passed. The `tauri` stage cannot compile
here — `glib-sys` needs the system libglib2.0 development files and this
sandbox has no root — so the Rust shell was verified only by
`test_the_shell_is_valid_rust.py` in the `py` stage; it compiles on the Windows
host. No packaged Windows or macOS build was made or walked in this
environment, so `tools/release_readiness.py` refuses complete stable
certification, as it did for 0.3.10 and 0.3.11.

The Windows installer, portable ZIP and engine ZIP, and the macOS disk image,
come from the hand-dispatched `desktop.yml` on the Windows host and a Mac —
this environment cannot dispatch Actions (the token lacks `actions: write`)
and cannot build Windows binaries, so those artifacts are not attached yet.
The 32 catalogs, `packs.json`, `packs-v0.3.12.zip`, the extension ZIP and
`SHA256SUMS.txt` were built from this tree and are attached.
