# Kriko 0.4.1 verification

Cut from `release/0.4.1` (from the 0.4.0 tag) to fix what the packaged 0.4.0 window
got wrong on screen. The automated gate had passed 0.4.0; four defects were seen
in the window. `0.4.1.json` holds the record.

## What was wrong and what changed

- **Two sets of window buttons.** `main.tsx` mounted `TitleBar` above the page and
  the header mounted it again, so the buttons were drawn at the top left and in
  the header, and the page sat 40 px lower. The window itself was already
  undecorated (`tauri.windows.conf.json`). `TitleBar` is now mounted once: in the
  header, or, on the Starting and offline screens that have no header, as a
  floating bar. `core:window:allow-internal-toggle-maximize` is granted so a
  double-click on the header maximises.
- **The agent menu ran behind the header.** It is now drawn in the page body,
  opens on the side with room, scrolls when it is longer than that room, and takes
  the arrow keys, Home, End, Escape and a click elsewhere.
- **Titles in a serif.** 0.4.0 set titles in Newsreader. Chivo Mono (Latin,
  Latin Extended with the Turkish letters and the lira sign, Vietnamese) ships
  inside the app and the display token reads it; Newsreader is removed.
- **Reconnect left the window offline.** `engine::restart()` stopped the old engine
  on a thread and left the status at `Failed`, which the page read straight after
  the press and gave up on. It marks `Starting` first now, and an offline window in
  the shell comes back by itself when the engine reports ready.
- **Found by the sweep.** An empty capsule in the header at 1320 px or less, a
  header agent that differed from the box's, a Settings choice cut short, the
  Sources panel clipping its buttons and scrolling sideways, a closed drawer that
  widened the page, a duplicate React key in the activity timeline, and the
  protocol note touching the card's edge.

## What was and was not observed

See `0.4.1.json`. Observed in the packaged window: every screen, four palettes,
two window sizes, a real sourced answer and follow-up (through opencode), Compare,
and Reconnect after killing the engine. Claude Code was slow on this machine at the
time and did not answer. Not observed: a fresh install, Stop, the upgrade from
0.4.0, the agent connection check, dragging and Windows snap.
